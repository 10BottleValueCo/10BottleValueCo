# 10BottleValue catalog import — development build

**Images awaiting confirmation:** KPV 5 mg (US), MOTS-C 20 mg (US), and Tesamorelin 20 mg (US) use the neutral image-pending placeholder because their source images visibly identify different compounds. No verified matching artwork was located. The snapshot retains the original image paths in its override records; the importer does not automatically save those override records to product metadata. A theme must explicitly display the placeholder; otherwise WooCommerce may show its default no-image display.

**Product document associations require reconciliation:** The dated source links certain strength-specific COA PDFs to several strengths. Examples include an ipamorelin 5 mg report linked to 5 mg and 10 mg offers, an NAD+ 500 mg report linked to 100 mg, 500 mg and 1000 mg offers, and a retatrutide 5 mg report linked to multiple strengths. These source associations are preserved, but neither the applicability of a report to a particular strength nor its relationship to a current lot has been established. Review and correct the associations before relying on them.

Twenty-two bundled vial images come from historical v19 artwork and differ from the current production checkout images at the same paths; the remaining 124 expected-location assets matched that checkout, and the placeholder is preview-only. Historical artwork is not evidence of current physical packaging. These are dated source comparisons, not a complete live-site image verification.

This is an installable **development** WordPress plugin for a staging WooCommerce store. Writes require `TBV_CATALOG_IMPORT_STAGING` set to true, WordPress environment `local` or `staging`, `DISABLE_WP_CRON` true, and `WP_HTTP_BLOCK_EXTERNAL` true. These flags prevent accidental use but do not isolate a connected server, block all third-party network activity, or make real data safe. PHP mbstring with Unicode case-folding is required; a clear error is returned if it is unavailable. It is not ready for a live cutover. It presents an administrator-only dry run and an explicit import action under WooCommerce → Catalog import. The bundled public catalog snapshot was extracted October 22, 2026 from source commit `5672c65ca153ec565256cd1d805f8a4a34fdb718`; it is not a live inventory feed. Physical stock, current prices, supplier rules, and changes since that date remain unverified.

The importer groups source rows by a deterministic source catalog identity and maps each stable migration key to a WooCommerce variation. It preserves dosage, warehouse, pack size, formulation, source price, source stock boolean and its evidence, source URLs/slugs as metadata, and source commit/date. It does **not** infer physical quantity. The bundled public product images and COAs are imported into the WordPress media library, deduplicated by source identity and checked against their original SHA-256; no remote URL is fetched. The three explicitly pending images remain placeholders, not asserted photos. Some source images have older product labels and require visual review or replacement before use.

New parents are drafts; variations are children of those drafts. The importer refuses to modify published products, variations with managed stock, existing unowned products with a matching name, or an existing offer that is not owned by this importer. A dry run validates the entire input and reports planned counts. Before updating previously imported drafts, it compares a saved baseline for parent name, image, managed attributes and provenance, and for variation price, image, stock status, attributes and importer-managed metadata. A missing baseline or an operator edit stops the import rather than silently overwriting the edit. Source keys that change while retaining an existing selector identity, unmanaged children, duplicate source indices, and mismatched store currency also stop the dry run. Bundled/previously imported media hashes are also checked; changed source images or removed COAs require review. Missing rows never delete products or attachments. A database-unique lock prevents simultaneous imports. Initial parent baselines are refreshed after the thumbnail and variable-product synchronization writes. A crash or interruption may leave a partial import or a lock: inspect the affected drafts and media, back up the database, then deliberately clear `_tbvi_import_lock` only after the interruption is understood. Each batch rechecks current data before writing, but the operation is not a database transaction. A killed server request can leave a partial batch or non-expiring job/import lock requiring inspection and deliberate recovery; restarting an already-applied batch is idempotent when its baseline remains unchanged. The initial full dry-run/preflight is read-only, but its duration and the per-batch timeouts still need measurement on the selected host. Re-run the dry run and reconcile before retrying.

No customers, orders, payments, credits, shipping rules or supplier data are imported. Existing unowned catalog products are not adopted; reconciliation and an explicit stable ID mapping are required to bring them under management. The source's direct product URLs/slugs are retained as metadata but redirects are not yet created. The image and COA attachment IDs are preserved, but frontend linking to every imported document and visual parity have not been verified. Additional production catalog fields, exact frontend presentation, stock synchronization, images beyond the bundled snapshot, and current prices require separate work and verification. Product publication and live checkout are outside this development plugin's task.

A compatible JSON file can be uploaded by a WooCommerce manager or the bundled snapshot selected. The form and each batch request are capability- and nonce-protected. The import runs automatically in requests of at most two offers while its admin page is open. Progress and an allowlisted public catalog copy are stored in a non-autoloaded, owner-bound job; after closing the page the same manager can reopen the active job and resume. No cron or automatic retry is assumed. An error stops the job for inspection; cancellation retains all completed drafts and media. Input paths are constrained to bundled assets; uploaded JSON cannot fetch remote media. Place only reviewed public assets in the plugin's assets folder. The earlier ZIP was exercised through the authenticated WordPress upload form and handler in a disposable PHP-WASM/SQLite fixture; this was not a manual browser click or a real-host test.

Testing is performed against a disposable copy of the sanitized WordPress/WooCommerce preview database and a separate temporary uploads directory. The exact dated source snapshot is dry-run as 66 product groups and 166 offers. For destructive-safe full-import tests, the same rows and public media are loaded into an isolated fixture with synthetic names and source keys, and the first and repeated imports are reconciled. No live customer or order data is used. See the adjacent development test receipt for the exact run and count; the real-host installer and limits remain untested.

Before the two October 26 image corrections, local development checks passed 71/71, including an exact 66-product/166-offer snapshot dry run, an 83-step import of 166 synthetic-key offers, repeat import, 146 deduplicated importer-owned image/COA attachments, interrupted/resumed jobs, and authenticated/invalid-nonce/anonymous AJAX checks. A separate JavaScript harness passed 4/4 controller checks. Local PHP-WASM measurements in one process: fresh two-offer batch 2.575 s, maximum of 83 batch steps 2.071 s, full 166-offer preflight with existing media 2.247 s, and a later two-offer batch on the largest parent 0.381 s. These are not real-host HTTP or timeout measurements.

After the two October 26 image corrections, the isolated fast regression passed 64/64, including the full 66-product/166-offer snapshot dry run and an actual WooCommerce import of all three pending-image offers without incorrect thumbnails. A separate snapshot comparison confirmed that the other 164 rows, source metadata, and all COA associations remained unchanged. The JavaScript controller harness passed 4/4. The 71-check full import and timing measurements above were run before those image corrections; they were not rerun afterward.
