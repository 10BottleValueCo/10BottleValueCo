# Catalog importer source — development only

This is the source and reproducible packager for the existing **draft-only** WooCommerce catalog importer. It uses the included dated public snapshot, not a live feed. It requires explicit administrator action and an open admin page; it does not automatically sync the current store. Do not activate it on a live store or a site with real customer, financial, or provider data. See the included plugin README for operation, known asset/document questions, nontransactional recovery and limitations.

`python3 build.py /absolute/new/output.zip` reads the four tracked plugin files and 147 public assets from the pinned Git commit in `public-assets.json`, checking each SHA-256. The pinned commit must exist in the local Git object database; a shallow clone may need that commit fetched. The output path must not already exist. The ZIP is deterministic for the same source and Python/zlib version; it is not a binary release or evidence of a real host. Source media include historical artwork and unverified report associations. The builder never downloads or reads credentials.

For isolated local tests, set absolute `TBV_WP_TEST_RUNTIME` to the sanitized fixture runtime and `TBV_CATALOG_IMPORT_DIRECTORY` to the extracted ZIP plugin directory, then run `node test.mjs` and `node test-admin-ui.mjs`. The first test creates and modifies fixture products in a copied, SHA-256-checked disposable database; use no real WordPress database. Set `TBV_CATALOG_IMPORT_ZIP` to the exact artifact and run `node install-test.mjs` for the WordPress upload handler test. These tests need the existing WordPress Playground/PHP-WASM dependency runtime, SQLite and the recorded sanitized fixture; they do not establish production host compatibility, actual prices/stock, current catalog, WooCommerce extension behavior or production readiness.

On 2026-10-27 the exact source-built v4 package (SHA-256 `b8a91e357de35249c015800987e5bdf555480979d8c45bf35dba85c2bdf05fa6`) passed the authenticated WP upload form/handler in the disposable fixture, 72/72 isolated PHP/Woo checks including an 83-batch synthetic-key import and repeat, and 4/4 admin controller checks. With each of the staging flag absent, production environment, cron enabled or outbound HTTP allowed, 5/5 checks rejected write operations without an active-job write. These are fixture results, not real-host, inventory, security-audit or live-sync proof. A second build from the same source produced the same SHA-256.
