# Synthetic customer and order migration lab

This development plugin is a guarded, isolated rehearsal. It only accepts explicitly synthetic IDs and `.invalid` email addresses, creates pending test orders with historical status and payment evidence retained separately, and registers no routes or UI. It is **not** a production importer, payment reconciler, credit ledger, or account migration. Run its tests only in a disposable WordPress/WooCommerce environment with HTTP and cron blocked; local flags alone cannot prevent every third-party side effect. The runtime must be marked local/staging; the test harness accepts only the recognized sanitized database hash and rejects SQLite sidecar files.

`TBV_WP_TEST_RUNTIME=/path/to/isolated/runtime node wordpress-migration/synthetic-import-lab/test.mjs` runs the fixture on WooCommerce HPOS; set `TBV_TEST_CLASSIC=1` to test classic storage, or `TBV_EXPECT_GUARD=1` for the disabled-runtime guard. `recovery-test.mjs` exercises interrupted synthetic requests with the same runtime and storage selection.

An identical retry checks selected destination fields, including the item subtotal and total, shipping line and aggregate amounts, unexpected fee/coupon/tax lines, discounts and refund records, before classifying an existing fixture as unchanged. These checks are deliberately narrower than a full order reconciliation and do not cover all possible WooCommerce or extension fields. The tests directly insert and delete a fictional refund record only to verify mismatch detection; they do not call a payment gateway or issue a refund. Imports do not create refunds or invoke `payment_complete`.

Writes are nontransactional. Recovery requires manual investigation of reservations and a caller's assertion that the old worker has stopped, which this code cannot prove. Real source schema, order history, guest identity, taxes, discounts, real product links, payment settlement, credits, affiliates, real-host concurrency, external extensions and complete reconciliation remain unverified. Do not run this lab on real customer or financial data or treat its tests as authorization to cut over.

The fixture contract optionally includes explicitly fictional billing and shipping addresses. The lab writes those fields to Woo orders and rejects changed destination addresses on retry or recovery. This does not establish real schema compatibility, customer-profile address migration, guest orders, null handling, international address rules, or production readiness. Set `TBV_TEST_ADDRESSES=1` when running `recovery-test.mjs` to exercise interruptions with synthetic addresses. `TBV_EXPECT_PRODUCTION=1` tests refusal in the production WP environment.

A second synthetic order shape exercises one to twenty fictional lines, each with a synthetic source line ID, name, quantity, subtotal and total. Amounts must balance and each line subtotal must equal total: discounts, taxes and refunds are deliberately not modeled. Optional explicitly tagged synthetic product/variation references are described below. Source line IDs are stored as item metadata and compared independently of Woo item order; edited or duplicate IDs block retry. Set `TBV_TEST_MULTILINE=1 TBV_TEST_ADDRESSES=1` for recovery-test.mjs to exercise interrupted multi-line/address imports. This is a fictional contract, not an assertion about the actual source schema or production migration readiness.

Synthetic product references must be unique tagged test records with a correct parent/variation relationship; no mapping is inferred from names, SKU or price. Historical order line amounts remain independent of later product-price changes. Set `TBV_TEST_PRODUCT_MAPPING=1` alongside `TBV_TEST_MULTILINE=1 TBV_TEST_ADDRESSES=1` for the interrupted-write recovery checks. This fixture does not prove a real catalog mapping, a transactional import, or stock and extension behavior on a real host.

An explicitly `null` customer ID in this fictional fixture represents an unlinked order. The test writes Woo customer ID `0` and does not attach an account by billing email, even if it matches a fictional customer. Missing or malformed references are rejected; changes to a source or destination owner require review. `TBV_TEST_GUEST=1 TBV_TEST_ADDRESSES=1 TBV_TEST_MULTILINE=1 TBV_TEST_PRODUCT_MAPPING=1` exercises interrupted unlinked-order recovery. A null in the real source has not been examined and must not automatically be interpreted as a guest order. This lab does not migrate actual guest records.
