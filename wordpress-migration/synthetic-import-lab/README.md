# Synthetic customer and order migration lab

This development plugin is a guarded, isolated rehearsal. It only accepts explicitly synthetic IDs and `.invalid` email addresses, creates pending test orders with historical status and payment evidence retained separately, and registers no routes or UI. It is **not** a production importer, payment reconciler, credit ledger, or account migration. Run its tests only in a disposable WordPress/WooCommerce environment with HTTP and cron blocked; local flags alone cannot prevent every third-party side effect.

`TBV_WP_TEST_RUNTIME=/path/to/isolated/runtime node wordpress-migration/synthetic-import-lab/test.mjs` runs the fixture on WooCommerce HPOS; set `TBV_TEST_CLASSIC=1` to test classic storage, or `TBV_EXPECT_GUARD=1` for the disabled-runtime guard. `recovery-test.mjs` exercises interrupted synthetic requests with the same runtime and storage selection.

An identical retry checks selected destination fields, including the item subtotal and total, shipping line and aggregate amounts, unexpected fee/coupon/tax lines, discounts and refund records, before classifying an existing fixture as unchanged. These checks are deliberately narrower than a full order reconciliation and do not cover all possible WooCommerce or extension fields. The tests directly insert and delete a fictional refund record only to verify mismatch detection; they do not call a payment gateway or issue a refund. Imports do not create refunds or invoke `payment_complete`.

Writes are nontransactional. Recovery requires manual investigation of reservations and a caller's assertion that the old worker has stopped, which this code cannot prove. Real source schema, order history, guest identity, taxes, discounts, multi-line orders, payment settlement, credits, affiliates, real-host concurrency, external extensions and complete reconciliation remain unverified. Do not run this lab on real customer or financial data or treat its tests as authorization to cut over.
