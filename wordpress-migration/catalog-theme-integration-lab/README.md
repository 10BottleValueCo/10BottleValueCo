# Importer-to-theme integration — disposable fixture

This test exercises the source-built development importer, public catalog adapter, and staging theme together. It requires extracted, trusted local ZIPs and a specifically hash-checked sanitized WordPress/PHP-WASM fixture. It copies the fixture database and uploads into a temporary directory, deletes only products in that copy, imports twelve synthetic-key offers as drafts, repeats the dry run, then publishes the single synthetic parent only in that disposable copy so the public catalog and native Woo cart can be checked. It makes no real orders, uses no customer data, and does not publish products in a real store. HTTP and WordPress cron are disabled in the fixture.

Set absolute `TBV_WP_TEST_RUNTIME`, `TBV_THEME_DIRECTORY`, `TBV_CATALOG_DIRECTORY`, and `TBV_IMPORTER_DIRECTORY` to the trusted runtime and extracted plugin/theme directories, then run `node test.mjs`. The test verifies source-to-output IDs, price, dose, warehouse, pack, option labels and all twelve native cart variation IDs. It checks PHP/Woo behavior directly; it is not a browser, checkout, inventory, current price, live host, or complete visual parity test. Deleting or publishing real catalog items is outside the test's scope; never change the recognized database hash to use a real database.

For the browser integration, run `serve.mjs` with the four directory variables above plus absolute `TBV_HOMEPAGE_DIRECTORY`. It binds only `127.0.0.1:9476`, checks the sanitized fixture database hash, creates products using the importer with synthetic identities in a temporary copied database/uploads directory, and publishes the synthetic parent only there. Checkout, accounts, arbitrary API writes and non-fixture cart IDs are blocked. Set absolute `TBV_PLAYWRIGHT_MODULE` and `TBV_CHROME_BIN` and run `test-browser.mjs` in a second terminal. Set `TBV_SITE_PREFIX=root` on both commands for a root install; otherwise `/wordpresspreview` is used. Set `TBV_TEST_DESKTOP=1` for a 1440px viewport; the default is 390px. Stop the server when done. The server mounts trusted local package directories and is a test harness, not a secure preview host; do not connect it to real data or expose it to a network.

On 2026-10-27, the v12 staging theme/catalog and v4 catalog importer were tested from their extracted ZIPs: all twelve synthetic warehouse/pack/formulation combinations returned the expected posted variation, cart variation, quantity and fixture price in a 390px `/wordpresspreview` browser and a 1440px root browser. The harness rejected checkout, accounts, admin, Store API checkout and a non-fixture item ID. The browser test blocked external requests and reported no page errors or HTTP errors. This is selection/cart coverage for a synthetic imported product, not complete visual comparison or a real checkout.

`test-product-link.mjs` checks a fixture in which the named formulation precedes the empty formulation. It selects a five-pack from the card, reloads the product page, adds it to the Woo cart, and follows the native-cart product link back, verifying the same option, warehouse, pack, price and variation ID. It covers both empty and named options; `TBV_TEST_DESKTOP=1` selects desktop as above. Existing links without an explicit option retain their prior default; newly generated preview links distinguish an explicit empty option.
