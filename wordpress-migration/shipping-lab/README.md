# Warehouse shipping development plugin

Local development foundation for a WooCommerce shipping method. It is not activated or deployed. It registers a zone-based method and reads rates, eligibility, currency, source, status and version from its editable per-instance WordPress settings; no live merchant rates or destination lists are embedded as public code constants. An applied, valid WooCommerce free-shipping coupon zeroes the calculated rate. Order-line subtotals are divided by warehouse and only worldwide subtotal determines a tier, matching the current application source tested here. A zero-priced worldwide line still uses worldwide service eligibility and the configured zero-subtotal tier; it must not be mistaken for a US-only cart. Rule version is recorded on the resulting Woo shipping rate.

`TBV_WP_TEST_RUNTIME=/path/to/isolated/runtime node wordpress-migration/shipping-lab/test.mjs` exercises actual WordPress and WooCommerce using a disposable copy of the sanitized preview database. The fixture uses shipping prices visible in the current store's source, explicitly marked unverified, and synthetic destination lists; these are test evidence, not authorization or proof of current commercial terms. The optional `TBV_WP_TEST_RUNTIME` points at the local WordPress test runtime. The plugin itself has no rates or country list defaults.

Before deployment: confirm exact rates/countries and boundary semantics, map real product metadata and both warehouses; test shipping zones, promotion stacking and free-shipping selection through checkout, US-only and mixed carts, tax configuration, refunds, checkout and historical order snapshots. Multiple WC shipping packages are deliberately not quoted yet to prevent double charging; define allocation first. WooCommerce taxes use the merchant-configured tax status and have not been validated. No orders or provider calls were performed. This is not a complete shipping migration.
